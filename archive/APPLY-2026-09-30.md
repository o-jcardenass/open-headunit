# Applying the 2026-09-30 rig changes on the tester PC

Two commits landed on top of your `a9cdf0ac` and change how a round is run and read. This is what the
tester PC has to do once, in order. Nothing here touches a device.

| Commit | What changed |
|---|---|
| `69c31825` | The `rig-round` workflow and the `rig-grader` agent are gone. `/rig-round` is host-driven: the host plans, grades and drafts; `rig-executor` still runs each run in the foreground. |
| `eca838e5` | `TESTING-TEMPLATE.md` §7a is split into `rig-quirks/` (per-unit and per-topic files, entries moved verbatim). §7a is now the index. `/rig-round` step 1 reads only the parts a round needs. |

**Why:** on a Pro allowance the workflow only re-read the brief and the template in a fresh Sonnet
context per grade, and the template was 120 KB read whole every round. A round now reads about
60 to 70 KB instead.

## 1. Pull the branch

From the transfer worktree:

```bash
git fetch fork
git checkout transfer/rig-rounds
git merge --ff-only fork/transfer/rig-rounds
git log --oneline -3    # the top commit is this file's; eca838e5 and 69c31825 below it
```

## 2. Remove what no longer exists

```bash
rm -f .claude/workflows/rig-round.js
rm -f .claude/agents/rig-grader.md
rmdir .claude/workflows 2>/dev/null || true
```

If `.git/info/exclude` lists `/.claude/workflows/`, that line can go; leaving it is harmless.

## 3. Re-copy the skills and the agent

The `rig-round` skill changed in both commits, so the installed copy is stale:

```bash
mkdir -p .claude/agents .claude/skills
cp rig-sdlc/agents/rig-executor.md .claude/agents/
rm -rf .claude/skills/rig-round .claude/skills/rig-diagnose
cp -r rig-sdlc/skills/rig-round rig-sdlc/skills/rig-diagnose .claude/skills/
```

## 4. Restart Claude Code

Agents and skills are registered at start-up, so a running session still knows the old
`rig-grader` and the old skill text.

## 5. Check it took

```bash
ls .claude/agents .claude/skills                                   # rig-executor.md; rig-round, rig-diagnose
test ! -e .claude/workflows/rig-round.js && echo "workflow gone"
grep -c "Workflow" .claude/skills/rig-round/SKILL.md                # 0
grep -c "rig-quirks" .claude/skills/rig-round/SKILL.md              # 2 or more
ls rig-quirks/units rig-quirks/topics                              # 6 unit files, 7 topic files
```

In the new session, `/agents` should list `rig-executor` and no `rig-grader`.

## 6. What changes in a round

- **Reading:** step 1 of `/rig-round` reads the template without §7b and §8, then
  `rig-quirks/topics/tooling.md`, the `rig-quirks/units/` file for each unit in the brief, and the topic
  files its runs touch. Setup notes say which quirk files were read.
- **Grading:** the host grades each run itself after its own `grep -c`, and writes
  `<id>.grade.json` next to the evidence as before. There is no `Workflow` call anywhere in a round.
- **New quirks** go in the `rig-quirks/` file they belong to, never back into §7a.

## One thing to decide

`/rig-round` step 6 uploads evidence as `rig-evidence-<thread>-round<N>`, one release per round.
`README.md` and `TESTING-TEMPLATE.md` §7 say **one release per thread** (`rig-evidence-<thread>`,
created on the first round, one asset per round), because per-round releases cluttered the tag list.
Align step 6 with §7 unless there is a reason for the difference, and say which in the next round's
Setup notes.
