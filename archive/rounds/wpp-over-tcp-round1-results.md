### Why

This repo has **no protobuf Gradle plugin** — `app/build.gradle.kts` pulls in only the
`com.google.protobuf:protobuf-java:3.25.1` *runtime*. The generated Java is committed into the
source tree at `app/src/main/java/com/andrerinas/openheadunit/aap/protocol/proto/Wireless.java`
and regenerated by hand with `app/src/main/proto/gen.sh` (a local `protoc` 25.1 →
`--java_out=../java/`).

`8d369ac5` adds three messages and two fields to `wireless.proto`:

- `message WifiProjectionProtocolInfo { ip_address = 1; port = 2; }`
- `message WppCarInfo { … body_type = 9; }`
- `message ProjectionDeepLinkData { … security_mode = 7; }`
- `WifiVersionRequest` gains `car_info = 5` and `wpp_info = 6`

…but `git show 8d369ac5 --stat` touches **0** lines of `Wireless.java`. The committed
`Wireless.java` still stops at `WifiSetupInfo` and its `WifiVersionRequest` has only `major`/`minor`.
So `Wireless.WppCarInfo`, `Wireless.WifiProjectionProtocolInfo`, `Wireless.ProjectionDeepLinkData`,
`WifiVersionRequest.Builder.setCarInfo(...)` and `.setWppInfo(...)` do not exist as types/methods,
and the four new Kotlin files plus `NativeAaHandshakeManager` that reference them do not compile.

Precedent: the previous `wireless.proto` change, `ec1b79cd` ("proto: model the rest of the Android
Auto wireless handshake", 2026-08-05), regenerated and committed `Wireless.java` in the same commit.
`8d369ac5` skipped that step.

### The fix (coding session)

```bash
cd app/src/main/proto
protoc wireless.proto --java_out=../java/     # protoc 25.1, per gen.sh
git add app/src/main/java/com/andrerinas/openheadunit/aap/protocol/proto/Wireless.java
```

Then re-run `run_unit_tests.sh` to confirm 18/0 on the two new suites and no regressions, and this
round can be re-queued unchanged. `protoc` is **not** installed on the rig host, so this cannot be
done from the testing session; and regenerating + force-pushing generated code onto the candidate
branch is a coding-session call, not a testing-session one.
