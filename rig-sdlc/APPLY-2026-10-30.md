```
Run git fetch fork, then follow rig-sdlc/APPLY-2026-10-30.md as it is on fork/transfer/rig-rounds
```

Then restart Claude Code if step 1 says the skills changed. No unit is changed except in step 4, and step 4 only
reads.

## What changed since your last pull

- **rig-lib, Bluetooth:** `rig_forget.py`, `rig_pair.py`, `rig_bt.py` and `bt-helper/` (an instrumentation APK built
  from source with the SDK's own tools). `check --fix` now forgets a `nobond=` and pairs a `bond=` by itself: through
  the Bluetooth API on API 29 and up, and through the Settings screens below that. It prints an OPERATOR line only
  when both fail.
- **rig-lib, reliability:** a radio read falls back to `settings get global` on API 17/19, the radio read-back waits
  35 s, `clocks` reads `logcat -v time`, the device-file sweep reads errors, the app-running check works without
  `pidof`, captures restart by themselves (`rl_capture.sh`), `rl_connect` polls wireless adb, and `rl_broadcast`
  checks the app's `"ok":true`.
- **Role names:** `rig-sdlc/APPLY-2026-10-30-role-names.md`. A hyphen role name must never pass `rig_preflight.sh`.
- **Queue:** `main-smoke-round1-brief.md` is trimmed to M5, M2 and M7; `bt-helper-round1-brief.md` is new (15).
  `rig-lib/main_smoke_brief.md` pins rig-lib `1870c258e`.

## Steps

### 1. Fast-forward and sync, the branch copy wins

Use the worktree you ran `pr-train-20261030` round 1 in (your main checkout has an untracked `rig-lib/` and
`progress.pid` in the way; do not delete them).

```bash
git fetch fork
git checkout transfer/rig-rounds
git merge --ff-only fork/transfer/rig-rounds
git log -1 --format=%h                      # d2dcbc144 or later
python3 -I rig-sdlc/rig-env/rig_sync.py sync --prefer branch
python3 -I rig-sdlc/rig-env/rig_sync.py status; echo "status exit=$?"
```

`status exit=0` is required. If `sync` copied a skill or an agent, tell the operator to restart Claude Code after
this file is done.

### 2. The rig-lib tests

```bash
bash rig-lib/tests/test_rig_lib.sh 2>&1 | tail -1
```

`96 passed, 0 failed` is required. If `/tmp` is full, run it with `TMPDIR=<a folder with space>` in front.

### 3. Build the Bluetooth helper once

```bash
bash rig-lib/bt-helper/build.sh
```

The last line must be the path of `rig-bt-helper.apk`. If it says `no build-tools or platform`, set `ANDROID_HOME`
to the SDK the app builds use and run it again. Do not install it: `rig_bt.py` installs it when a round needs it.

### 4. Role names, read only

Follow `rig-sdlc/APPLY-2026-10-30-role-names.md` unless it was already applied. Check it either way:

```bash
rig_preflight.sh D-HU D_POCO; echo "exit=$?"
rig_preflight.sh D-FOO; echo "exit=$?"
```

The first must check both units (a table row for each). The second must fail with a non-zero exit.

### 5. Report

Write `rig-apply-20261030-results.md` in the worktree root: one line per step with its outcome (the commit from
step 1, the test line from step 2, the APK path or the error from step 3, both preflight results from step 4), and
any step that failed with its output. Commit only that file with the message
`Rig apply: the 2026-10-30 changes on the tester PC` and push to fork.

The next round to run is Queue 15, `bt-helper-round1-brief.md`. It needs no app build.
