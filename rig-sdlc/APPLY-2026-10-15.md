# Applying the 2026-10-15 rig changes on the tester PC

**For the operator:** start Claude Code in this worktree and type one line:

```
Run git fetch fork, then follow rig-sdlc/APPLY-2026-10-15.md as it is on fork/transfer/rig-rounds
```

(The branch was squashed, so the copy in this checkout is older than this one.)

Then restart Claude Code when the agent asks. That is all you type, now and later.

## Why this is needed

Claude Code loads skills and agents only from `.claude/`, and only when a session starts. Those live
files and their mirror in `rig-sdlc/` drifted apart: on 2026-10-15 the rig's `rig-round` skill was behind
the branch, and its `rig-executor` was ahead of it. Nothing carried an edit from one side to the other.

`rig-sdlc/rig-env/rig_sync.py` now does that, both ways. The rig may edit its own skills, agents, hooks and
`TOOLS.md` in place, and the coding side may edit them here. `sync` compares the live copy, the branch copy
and the copy at the last sync, and carries each edit to the side that does not have it yet. When both sides
changed one file, it merges them. `/rig-round` runs it at start and at `approve`.

This file runs the first sync. Every rig edit made so far is already on the branch, so the branch copy wins
where the two differ.

**The branch history was squashed on 2026-10-15** to a base commit plus one commit per queued brief, and the
old history was deleted. Step 1 resets this checkout to the new history once.

## Steps for the agent

Run each block from the root of this worktree. Nothing here touches a device. Stop and report if a
check gives a different answer.

### 1. Reset to the squashed branch (once)

First check that this checkout holds no commit or change the fork never had. The reflog keeps every tip
`fork/transfer/rig-rounds` has had, so the check works after the fetch too. If either check prints anything,
stop and tell the operator: those changes must go onto the new branch by hand.

```bash
git fetch fork
git checkout transfer/rig-rounds
git log --oneline HEAD --not $(git reflog show --format=%H fork/transfer/rig-rounds)   # must print nothing
git status --short                                                       # must print nothing
git reset --hard fork/transfer/rig-rounds
test -f rig-sdlc/rig-env/rig_sync.py && echo "reset"
```

### 2. Keep `.claude/` out of the branch

```bash
EX="$(git rev-parse --git-path info/exclude)"
grep -qxF '/.claude/' "$EX" || echo '/.claude/' >> "$EX"
```

### 3. First sync

There is no earlier sync, so `--prefer branch` settles every file that differs. A file that exists only on
the rig still comes IN.

```bash
mkdir -p .claude
rm -f .claude/rig-sync-base
python3 -I rig-sdlc/rig-env/rig_sync.py sync --prefer branch
```

If it lists `IN` paths, commit them by name (`Rig SDLC: <what changed>`), push to `fork`, and run
`python3 -I rig-sdlc/rig-env/rig_sync.py sync` again.

### 4. Check

```bash
python3 -I rig-sdlc/rig-env/rig_sync.py status     # prints "in sync"
git status --short                                  # prints nothing
```

### 5. Rig script changes

Already done on the rig (list in `archive/RIG-SCRIPTS-2026-10-15.md`). Check one of them:
`grep -c MAX_WORKERS ~/Coding/StudioProjects/rig-toolkit/build_hur.sh` prints 1 or more. If it prints 0, do that file's items.

### 6. Ask the operator to restart

Tell the operator: "The rig skills are in sync with the branch. Restart Claude Code before the next `/rig-round`."

After the restart, `/agents` lists `rig-executor` and `/rig-round` appears as a command.
